# Vidgoo على Render المجاني

بوت لتنزيل الوسائط من منشورات تويتر/X وإنستغرام وتيك توك العامة، مع webhook يناسب Render المجاني. أرسل الرابط ثم اختر **فيديو** أو **صوت MP3** أو **صور**. يحافظ على ضغط الفيديو الكبير تحت 50MB، ويضغط الصوت الكبير أيضًا دون تقطيع مدته، ويحذف الملفات المؤقتة بعد الانتهاء.

## الاستخدام

- 🎬 **فيديو**: أول فيديو في المنشور، مع دمج الصوت وضغط الحجم عند الحاجة.
- 🎵 **صوت MP3**: استخراج الصوت من أول فيديو في الرابط؛ لا يدعم روابط اسم أغنية أو ملف تعريف صوت TikTok.
- 🖼 **صور**: حتى أول 20 صورة من المنشور، بألبومات من 10 صور. لا يحوّل الفيديو إلى صور ولا يرسل أغلفة الفيديو كأنها صور المنشور. الصور تُجهَّز كـJPEG للعرض في تلغرام؛ البانوراما والصور ذات الأبعاد الكبيرة تُرسل كملف أصلي تحت 50MB. الصور المتحركة تُعرض بإطارها الأول.

يمكن استعمال الأوامر مباشرة:

```text
/video رابط_المنشور
/audio رابط_الفيديو
/photos رابط_منشور_الصور
```

خيارات كل رابط صالحة 15 دقيقة ولمرة واحدة وللمستخدم والمحادثة اللذين طلباها. لإخراج نوع آخر أعد إرسال الرابط. عند إعادة تشغيل الخدمة تُلغى الخيارات القديمة؛ أعد إرسال الرابط كذلك. رابط الصور يجب أن يكون رابط منشور محدد، وليس رابط حساب أو بحث.

اختيار الصور لرابط Instagram Reel أو TV يُرفض فورًا قبل دخول طابور التحميل، مع توضيح اختيار الفيديو أو MP3. طلبات الصور لا تُعاد عند فشل الاتصال أو حظر المنصة، بما في ذلك `429` و`403`؛ مهلة الاتصال 12 ثانية والمهلة الإجمالية لأداة الصور دقيقة واحدة. يُوقف الطلب المتعثر بدل انتظار عدة دقائق وتعطيل الطلبات التالية. هذه الحدود لا تزيل حظر إنستغرام، وقد تفشل معها الصور على اتصال بطيء جدًا. إعدادات تنزيل الفيديو والصوت وجودتهما لم تتغير.

التنزيل بدون كوكيز حساب أو كلمات مرور. دعم الموقع لا يضمن نجاح كل رابط: قد تطلب المنصة تسجيل دخول، تحدّ الطلبات أو تحجب الخادم، حتى مع بعض المنشورات العامة. إذا لم توجد صور أو مسار صوت في المنشور، يعرض البوت رسالة توضيحية بدل إرسال ملف خاطئ. معالجة ملف واحد في كل مرة، مع ثلاثة طلبات انتظار كحد أقصى، لتقليل استهلاك ذاكرة خطة Free.

## تحديث GitHub

استبدل `bot.py` و`requirements.txt` في المستودع الذي تربطه بخدمة Render بهذه النسخة. ارفع الملفات في جذر المستودع، وليس داخل مجلد فرعي. يمكن رفع `README.md` و`.gitignore` و`.python-version` أيضًا. `render.yaml` جاهز لإنشاء خدمة جديدة بخطة Free عبر Blueprint؛ رفعه وحده لا يغيّر إعدادات الخدمة الموجودة.

المكتبات هنا تخص Vidgoo؛ استبدل متطلبات البوت السابق بالكامل ولا تجمعها مع متطلبات aiogram.

## إعداد خدمة Render الحالية

1. أبقِ نوع الخدمة **Web Service** وخطة الحوسبة **Free**.
2. استخدم الفرع `main`، واترك Root Directory فارغًا إذا رفعت الملفات في جذر المستودع.
3. ضع Build Command:

```sh
python -m pip install -r requirements.txt
```

4. ضع Start Command:

```sh
python bot.py
```

5. ضع Health Check Path: `/health`.
6. في **Environment** أبقِ `BOT_TOKEN` بقيمة توكن BotFather. لا تضع التوكن في ملف على GitHub. لا تحتاج `.env` على Render.
7. الكود يقرأ رابط الخدمة تلقائيًا من `RENDER_EXTERNAL_URL`، ويفتح المنفذ الموجود في `PORT`. إذا طلب رابط الخدمة، أضف `WEBHOOK_URL` بالقيمة `https://اسم-خدمتك.onrender.com` دون مسار.
8. بعد رفع التحديث أو دمجه في `main`، انتظر إعادة النشر التلقائية. إذا كانت معطلة اختر **Manual Deploy → Deploy latest commit**، وانتظر ظهور **Live** وسطر `Vidgoo webhook registered successfully`.
9. أرسل `/start`، ثم رابط منشور عام قصير واختبر خيارات الفيديو والصوت والصور حسب محتواه. يطلب webhook تحديثات `message` و`callback_query` حتى تعمل الأزرار.

تحتاج ميزات دمج الفيديو واستخراج MP3 والضغط إلى `ffmpeg` و`ffprobe`؛ يفحصهما الكود عند التشغيل كما في النسخة الأصلية. الصور تستخدم `gallery-dl` و`Pillow`، وهما مضافتان إلى `requirements.txt`. إذا كانت الأدوات غير متاحة في خادمك ستظهر رسالة واضحة في السجل.

## الاختبارات المحلية

بعد تثبيت المتطلبات، شغّل من جذر المشروع:

```sh
python -m unittest discover -s tests -v
```

الاختبارات لا تستخدم توكنًا حقيقيًا ولا تستدعي Telegram أو مواقع التواصل. تشمل webhook والأزرار والعزل بين المستخدمين وتنظيف الملفات؛ واختبار تنزيل صور عبر HTTP محلي باستخدام gallery-dl فعليًا، وتحويل MP4 محلي إلى MP3 وضغط الصوت باستخدام FFmpeg. اختبارات FFmpeg تُتجاوز إذا لم تتوفر الأدوات. نجاح هذه الاختبارات لا يؤكد إتاحة منشور معين من مواقع التواصل.

## حدود التشغيل المجاني

Render يدخل في خمول بعد 15 دقيقة دون طلبات واردة. رسائل Telegram تصل كطلبات webhook ويمكنها إيقاظ الخدمة، لكن أول رد قد يتأخر نحو دقيقة أو أكثر إذا احتاج Telegram إعادة إرسال الطلب. هذا تشغيل مجاني عند الحاجة، وليس ضمانًا لتشغيل 24 ساعة دون تأخير. تطبق أيضًا حدود ساعات التشغيل والباندويث الشهرية.

طلبات التحميل التي تم قبولها تنتظر في ذاكرة الخدمة، وتُفقد إذا أعاد Render تشغيلها أثناء الطلب. إذا توقف تنزيل طويل، أعد إرسال الرابط بعد استيقاظ البوت. الملفات مؤقتة، ويزيلها الكود بعد إرسالها. لا تعتمد على تخزين Render المجاني كنسخة احتياطية.

شغّل نسخة واحدة فقط بالتوكن نفسه. عند إيقاف الخدمة يترك الكود webhook مسجلًا حتى يستطيع Telegram إرسال الرسائل لاحقًا. النسخة لا تستخدم كوكيز حساب، وقد ترفض المواقع بعض الروابط أو تطلب تسجيل دخول كما في النسخة الأصلية.
